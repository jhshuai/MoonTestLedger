The current executable verifies the historical files, regenerates each delivery in a **new** temporary directory, and compares all six files byte-for-byte. Original gates 0/1/3 and source/plan/policy remain part of the check. This evaluator runs in the standard matrix for the two supported file CLI targets; original fixtures are never rewritten. A dependency/compiler/HTML/ZIP change that alters the representation fails this regression check.

Maintain `mtl-ci-delivery-v1` as a stable representation while supported. If a representation change is needed, introduce a new named profile and retain the existing v1 verification/generation path and these historical fixtures. Never refresh old golden hashes merely to make a changed formatter pass. Unknown profiles return `DeliveryProfileUnsupported` with instructions to keep the original files and use a compatible verifier; unsupported does not establish corruption. Malformed receipts, duplicate/noncanonical receipt fields and changed known-v1 members are still rejected. No automatic migration or cross-profile rewrite is implemented.

This corpus proves compatibility for these captured profiles across the tested revisions/targets; it is not evidence for all future compiler/dependency versions or every possible report. Checksums are integrity evidence, not signatures or sender authentication.
